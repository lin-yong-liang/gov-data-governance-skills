# 政务数据目录条目编制

## 定位与分工

- 本 skill：**单个数据资源的目录条目编制与交付**
- `metadata-standards-master-data`：全域目录体系、数据标准、基础库方法论

本 skill 的产物可直接作为共享平台/目录系统的录入底稿。

## 目录条目要素

| 区块 | 要素 |
|---|---|
| 基本信息 | 资源名称、资源代码、资源摘要、所属主题/领域、资源类型（库表/接口/文件） |
| 权属与权威源 | 提供方、数据 Owner、技术支撑单位、是否权威源、一数一源说明 |
| 共享开放 | 共享属性及依据、开放属性及依据、共享方式（接口/批量/库表）、更新周期 |
| 数据结构 | 库表名、字段清单、主键、外键、数据量、存储位置 |
| 数据项说明 | 中文名、英文名、业务定义、类型、长度、值域、是否必填、是否敏感 |
| 质量信息 | 完整性、准确性、时效性现状，已知问题 |
| 血缘 | 上游来源、下游使用方、加工链路 |
| 安全与分级 | 分类、分级（核心/重要/一般）、个人信息标识、敏感程度、脱敏要求 |
| 版本与审核 | 版本号、编制人、审核人、发布日期、变更记录 |

## 共享属性判定

| 属性 | 判定 | 要求 |
|---|---|---|
| 无条件共享 | 可提供给所有政务部门 | 明确数据项范围 |
| 有条件共享 | 按条件提供给指定部门 | 写明条件、用途、审批流程 |
| 不予共享 | 必须有法律法规或国务院决定依据 | 逐项列明依据条款，不能只写"涉密" |

## 开放属性判定

- **无条件开放**：可向社会公开，通常脱敏后以数据集/API 开放
- **有条件开放**：面向特定主体、特定用途，需申请与审核
- **不予开放**：涉及个人信息、重要数据、商业秘密或法定禁止情形

开放前必须做安全审查和脱敏，敏感个人信息不得开放。

## 分类分级填写（GB/T 43697）

- 分类：按业务领域（自然人、法人、自然资源、电子证照、信用、宏观经济）
- 分级：核心 / 重要 / 一般
- 个人信息：单独标识"敏感个人信息 / 一般个人信息"
- 敏感程度（内部管理）：公开 / 内部 / 敏感 / 涉密（涉密按保密法管理）

## 编制流程

1. **提取技术元数据**：表结构、字段、主外键、行数（脚本或平台导出）
2. **访谈提供方**：业务用途、权威源、更新周期、共享历史、已知问题
3. **编写数据项说明**：逐字段写业务定义、值域、是否必填、是否敏感
4. **补充质量与血缘**：引用最近一次质量稽核结果；记录上下游
5. **认定共享/开放属性与分级**：逐项写依据，不写"按惯例"
6. **审核发布**：提供方确认 → 数据局/目录管理部门审定 → 入库并记版本

## 一数一源说明

每个数据项必须回答：

- 权威源是哪个部门/系统？
- 本资源是权威源、同步副本还是加工结果？
- 与权威源不一致时以谁为准？
- 更新频率与同步方式是什么？

## 技术元数据提取脚本

`scripts/catalog_extractor.py` 可从 SQLAlchemy 兼容数据库提取表结构并生成中文目录草稿：

```bash
python scripts/catalog_extractor.py --conn "postgresql://user:pass@host/db" \
  --table t_person --schema public --output catalog_draft.md
```

- 支持 PostgreSQL、MySQL、SQLite、Oracle 等 SQLAlchemy 方言（取决于已安装驱动）
- 只读元数据与行数，不修改数据
- 自研平台若不兼容，可从平台导出字段清单后直接填 `assets/data_item_list_template.csv`
- 密码建议用环境变量传入，不要写在命令行历史里

## 交付物

- `assets/catalog_entry_template.md` — 目录条目正文模板
- `assets/data_item_list_template.csv` — 数据项级清单（可导入目录系统）
- `scripts/catalog_extractor.py` — 技术元数据提取

## 常见问题

- 目录只编到表级：必须细化到数据项级，否则共享方无法判断可用性
- 共享属性写"视情况"：必须三选一，不予共享要附法定依据
- 权威源不清：同一数据项多个部门都声称权威，需数据局裁定
- 更新周期写"实时"但没有接口：要与实际同步方式一致
- 敏感字段未标识：个人信息、重要数据必须逐字段标注

## 注意事项

- 目录条目中的联系方式、责任人要更新，避免"僵尸目录"
- 版本变更要留痕，共享方需要知道口径何时变过
