# 政务数据目录编制规范参考

## 依据

- 《政务数据共享条例》（2025-08-01 施行）
- 《政务信息资源共享管理暂行办法》（国发〔2016〕51 号）
- 《政务信息资源目录编制指南（试行）》（发改高技〔2017〕1272 号）
- GB/T 21063 政务信息资源目录体系
- GB/T 21062 政务信息资源交换体系
- GB/T 43697-2024 数据分类分级规则
- 本级政府政务数据管理办法与目录编制细则

> 各地目录系统字段名可能不同，以本级平台模板为准；本模板用于内容底稿。

## 目录要素

### 核心元数据

| 要素 | 说明 | 必填 |
|---|---|---|
| 资源名称 | 业务通用名称，避免技术表名 | 是 |
| 资源代码 | 目录系统唯一编码 | 是 |
| 资源摘要 | 一句话说明内容与用途 | 是 |
| 提供方 | 责任部门全称 | 是 |
| 所属主题 | 自然人和法人等主题分类 | 是 |
| 数据格式 | 库表 / CSV / JSON / 接口 | 是 |
| 更新周期 | 实时 / 日 / 周 / 月 / 年 | 是 |
| 共享属性 | 无条件 / 有条件 / 不予 | 是 |
| 开放属性 | 无条件 / 有条件 / 不予 | 是 |
| 数据项清单 | 细化到字段 | 是 |
| 联系人 | 姓名、电话、邮箱 | 是 |
| 版本 | 版本号与变更记录 | 是 |

### 扩展元数据

- 权威源标识、一数一源说明
- 数据量、存储位置、分区规则
- 质量得分与最近稽核日期
- 血缘（上游、下游）
- 分类分级结果、个人信息标识、敏感程度
- 脱敏规则、访问控制方式
- 共享方式与共享范围

## 共享属性判定

| 属性 | 判定标准 | 材料要求 |
|---|---|---|
| 无条件共享 | 可提供给所有政务部门，无附加条件 | 数据项范围清单 |
| 有条件共享 | 仅向满足条件的部门/场景提供 | 条件说明、审批流程、使用范围 |
| 不予共享 | 法律法规或国务院决定明确规定不得共享 | 逐项列明依据条款，不能只写"涉密""敏感" |

常见错误：

- 把"数据敏感"直接作为不予共享理由——敏感数据可脱敏共享
- 把"技术不支持"作为不予共享理由——应整改平台
- 有条件共享不写条件，实际变成"看关系共享"

## 开放属性判定

| 属性 | 判定标准 |
|---|---|
| 无条件开放 | 可向社会公开，通常脱敏后以数据集/API 开放 |
| 有条件开放 | 面向特定主体、特定用途，需申请审核 |
| 不予开放 | 涉及敏感个人信息、重要数据、商业秘密或法定禁止 |

开放前必须：

1. 完成分类分级
2. 完成安全审查
3. 对个人信息和敏感字段脱敏
4. 明确开放协议和使用约束

## 数据项编制要求

每个数据项至少写清：

- 中文名：业务人员能看懂
- 英文名：符合命名规范
- 业务定义：无歧义，避免循环定义
- 数据类型与长度
- 是否必填
- 值域或代码集（引用标准编号）
- 来源系统
- 是否敏感、是否个人信息

反例："状态：数据的状态"——没有信息量，必须写清有哪些状态、分别代表什么。

## 一数一源

同一数据项只认定一个权威源。目录中必须说明：

- 权威源部门与系统
- 本资源与权威源的关系（权威源 / 副本 / 加工）
- 同步方式与频率
- 不一致时的处理原则

## 常见驳回原因

1. 资源摘要写成技术描述，业务人员看不懂
2. 共享属性未三选一，或不予共享无依据
3. 数据项只到表级，没有字段清单
4. 更新周期与实际不符（写实时但实际日更）
5. 联系人失效，长期无人维护
6. 敏感字段未标识，个人信息未单独标注
7. 同一数据项多个部门都声称权威源
8. 版本变更无记录，共享方不知道口径变化

## 与分类分级衔接

目录条目中的分类分级结果应与数据分类分级清单一致。若目录条目与分类分级清单冲突，以分类分级清单为准，并回溯修正目录。
