# 政务指标口径对账

## 适用场景

- 两个报表/大屏/部门数据对同一指标给出不同值
- 数据中台改造后指标发生变化
- 领导或使用方质疑某个数字
- 合并、迁移或下线旧报表前验证口径
- 新指标上线前与旧口径比对

## 指标口径七要素

对账前必须逐项确认，任何一项不同都可能导致差异：

1. 业务定义：这个指标到底统计什么
2. 分子/分母：比率类指标尤其关键
3. 过滤条件：状态、类型、地区、事项范围
4. 时间口径：受理时间/办结时间/入库时间，自然日/工作日，时区
5. 统计粒度：按事项/按办件/按申请人/按主体
6. 数据来源：权威源、同步副本还是加工结果
7. 更新频率：实时/T+1/月报，数据截止时间

## 对账流程

1. **锁定指标与期间**：名称、定义、统计期、数据截止时间
2. **双方取数并留痕**：保存 SQL、执行时间、结果快照
3. **计算差异**：绝对差、百分比差，判断是否超容差
4. **维度下钻**：按地区、部门、事项类型、日期拆分，缩小差异范围
5. **定位根因**：对照七类根因逐一排除，找到第一处分歧点
6. **确认权威口径**：由数据 Owner 裁定，写入指标字典
7. **出报告并跟踪**：整改、重算下游、补监控规则

## 容差规则

- 默认容差 0.1%；可用 `--tolerance` 调整
- 法定统计、对外发布、考核指标建议容差为 0
- 差异必须解释清楚，不允许"调平"或"取中间值"
- 容差内也要记录，便于发现趋势性漂移

## 根因分类

| 类别 | 典型表现 | 排查方法 |
|---|---|---|
| 定义漂移 | 同名指标统计对象不同 | 对照指标字典和历史口径变更记录 |
| 过滤条件 | 一边含撤销/测试数据 | 对比 WHERE 条件、状态枚举 |
| 关联方式 | 内连接 vs 左连接导致漏数 | 对比 JOIN 类型和关联键 |
| 统计粒度 | 按办件 vs 按事项，重复计数 | 检查主键与去重逻辑 |
| 去重逻辑 | distinct 字段不同 | 对比 DISTINCT 字段组合 |
| 时间截断 | 受理时间 vs 办结时间 | 对齐时间字段和时区 |
| 刷新延迟 | 一边 T+1 一边实时 | 记录双方数据截止时间 |
| 加工缺陷 | 汇总表漏分区、重复跑批 | 核对分区、任务日志、幂等性 |

## 政务常见指标陷阱

- **办件量**：受理量、办结量、出件量是三个不同指标，常被混用
- **办结率**：分母是受理量、应办量还是按期应办量，差异巨大
- **共享调用量**：接口调用次数 vs 去重后的调用方数量
- **人口总数**：户籍人口、常住人口、实有人口、库内记录数不是一回事
- **好评率**：评价口径、默认好评是否计入
- **一件事一次办**：按事项数还是按办件数统计

## 对账脚本

`scripts/reconcile_metrics.py` 支持直接比较两个值，或从两个 CSV 汇总：

```bash
# 直接比较
python scripts/reconcile_metrics.py --values 125000 118120 --tolerance 0.001

# 从两个 CSV 取数
python scripts/reconcile_metrics.py --source-a a.csv --source-b b.csv \
  --metric case_count --date-col stat_date --date 2026-10-31
```

输出：双方值、绝对差、百分比差、是否在容差内。不访问网络。

## 注意事项

- 先对齐定义，再查数据；80% 的差异来自口径而不是 bug
- 保留取数 SQL 和结果截图，报告要可复现
- 确认权威源，避免"哪个数好看用哪个"
- 对账结论要回写指标字典，防止同样问题再次发生
