# 指标差异常见模式与排查清单

## 排查顺序（从高概率到低概率）

1. 定义是否一致（最高频，约一半问题）
2. 过滤条件是否一致
3. 时间口径与数据截止时间
4. 关联方式与关联键
5. 统计粒度与去重
6. 加工缺陷与任务异常

先问"这个指标怎么定义的"，再看 SQL。直接比对 SQL 容易陷入细节。

## 模式一：定义漂移

| 表现 | 示例 |
|---|---|
| 同名不同义 | "办件量"一边是受理量，一边是办结量 |
| 新旧口径并存 | 机构改革后事项合并，旧口径未更新 |
| 分子分母不同 | "办结率"分母分别为受理量、应办量 |

**排查：** 查指标字典、历史口径变更记录、需求文档。
**修复：** 由数据 Owner 确认唯一口径，更新指标字典，通知下游。

## 模式二：过滤条件

| 表现 | 示例 |
|---|---|
| 测试/撤销数据未排除 | 一边含 `status='作废'` |
| 地区范围不同 | 一边含省本级，一边只含市县 |
| 事项范围不同 | 一边含公共服务事项，一边只含行政许可 |

**排查：** 并排比较 WHERE 条件，逐条列出。
**修复：** 统一过滤条件或明确拆分指标。

## 模式三：关联方式

| 表现 | 示例 |
|---|---|
| INNER JOIN 漏数 | 主体信息缺失的办件被过滤 |
| 关联键不一致 | 一边用身份证号，一边用办件编号 |
| 多对多放大 | 关联后行数膨胀导致指标虚高 |

**排查：** 对比 JOIN 类型和关联键；先跑关联前后的行数。
**修复：** 统一关联逻辑；缺失主体应单独统计而非丢弃。

## 模式四：统计粒度

| 表现 | 示例 |
|---|---|
| 按办件 vs 按事项 | 一件事包含多个事项，重复计数 |
| 按申请人 vs 按主体 | 同一人多条记录 |
| 按日汇总再月汇总 | 跨日办件被重复统计 |

**排查：** 明确"一行代表什么"；检查 GROUP BY 字段。
**修复：** 统一粒度，必要时拆成两个指标。

## 模式五：去重逻辑

| 表现 | 示例 |
|---|---|
| DISTINCT 字段不同 | 一边按办件号，一边按申请人 |
| 多次调用未去重 | 共享调用量按接口次数 vs 去重调用方 |
| 历史版本未去重 | 同一主体多条版本记录 |

**排查：** 对比 DISTINCT / ROW_NUMBER 逻辑。
**修复：** 明确去重键和取最新版本规则。

## 模式六：时间截断与时区

| 表现 | 示例 |
|---|---|
| 受理时间 vs 办结时间 | 跨月办件归属月份不同 |
| 自然日 vs 工作日 | 办结时限计算不同 |
| 时区/时间格式 | 时间字段混用字符串与时间戳 |
| 数据截止时间不同 | 一边 0 点快照，一边 8 点快照 |

**排查：** 对齐时间字段、时区、截止时点。
**修复：** 指标字典明确时间口径；报表标注数据截止时间。

## 模式七：刷新延迟

| 表现 | 示例 |
|---|---|
| 一边实时一边 T+1 | 当日数据必然不一致 |
| 批量任务未跑完 | 汇总表分区缺失 |
| 上游补数未同步 | 历史数据被修正但下游未重跑 |

**排查：** 记录双方取数时间与任务状态。
**修复：** 对账前确认数据就绪；补数后触发下游重算。

## 模式八：加工缺陷

| 表现 | 示例 |
|---|---|
| 重复跑批 | 幂等性缺失导致数据翻倍 |
| 分区遗漏 | 新增地区未纳入 |
| 类型转换错误 | 字符串金额转数值丢精度 |
| 空值处理不同 | NULL 被计为 0 或排除 |

**排查：** 检查任务日志、分区、行数波动。
**修复：** 修复加工逻辑；补数据质量监控规则。

## 政务指标对账示例

### 办件量

- 受理量：统计期内受理的办件数
- 办结量：统计期内办结的办件数（可能是以前受理的）
- 出件量：证照/结果物发出的数量
- 对账时必须写明是哪一个

### 办结率

- 分母 = 受理量：反映当期受理件的办结比例
- 分母 = 应办量：反映按期办结情况
- 分母 = 办结量 + 在办量：反映存量结构
- 三种口径结果完全不同，不能互相替代

### 共享调用量

- 接口调用次数：含重复调用
- 去重调用方数：按部门/系统去重
- 成功调用量：剔除失败请求

### 人口总数

- 户籍人口：公安户籍口径
- 常住人口：统计口径
- 实有人口：含流动人口
- 库内记录数：含历史、重复、死亡未注销

## 容差建议

| 指标类型 | 建议容差 | 说明 |
|---|---:|---|
| 法定统计、对外发布 | 0 | 必须完全一致 |
| 考核指标 | 0 | 差异必须解释 |
| 内部经营分析 | 0.1% | 允许舍入差异 |
| 实时大屏 | 0.5% | 受刷新延迟影响 |

容差内也要记录，观察是否持续单向偏移。

## 对账记录规范

- 每次对账保留：指标名、期间、双方取值、取数 SQL、执行时间、数据截止时间
- 报告编号纳入指标字典或数据治理台账
- 结论必须写明权威口径，不能只写"已沟通"
