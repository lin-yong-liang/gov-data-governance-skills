# 元数据 · 数据标准 · 基础库主数据（政务/公共数据）

## 政务数据资源体系速查

| 层级 | 内容 |
|---|---|
| 基础库 | 人口、法人、自然资源和空间地理、电子证照、社会信用、宏观经济 |
| 主题库 | 营商环境、民生保障、社会治理、生态环保等 |
| 专题库 | 按应用场景组织，如"一件事一次办" |
| 部门库 | 各部门业务系统数据 |

权威源参考：人口—公安；法人—市场监管；空间地理—自然资源；社会信用—发改；宏观经济—统计。

## 政务信息资源目录

### 目录要素（核心元数据）

资源名称、资源摘要、提供方、数据格式、更新周期、共享属性、开放属性、所属分类、关键字、联系人、资源版本、数据项清单。

### 共享属性三分类

- **无条件共享**：可提供给所有政务部门
- **有条件共享**：按条件提供给指定部门
- **不予共享**：必须有法律法规或国务院决定依据

### 目录编制要点

- 一数一源：同一数据项只认定一个权威源
- 目录细化到数据项级，不能只到系统/表级
- 与权责清单、政务服务事项对应
- 建立目录更新机制（变更即更新、定期巡检）

### 三张清单

- 共享责任清单：各部门必须提供的数据
- 共享需求清单：使用方提出的需求
- 负面清单：不予共享的数据及法定依据

## 数据标准

### 数据元九要素（参考 GB/T 19488 思路）

| 要素 | 说明 | 示例 |
|---|---|---|
| 中文名 | 业务通用叫法 | 公民身份号码 |
| 英文名 | 遵循命名规范 | id_number |
| 业务定义 | 无歧义解释 | 公民身份的唯一标识号码 |
| 数据类型 | 字符/数值/日期 | CHAR |
| 长度/精度 | | 18 |
| 值域 | 枚举或范围 | GB 11643 规定 |
| 编码规则 | 引用标准 | GB 11643 |
| 数据 Owner | 权威源部门 | 公安局 |
| 来源系统 | 权威系统 | 人口基础库 |

### 命名规范要点

- 分层前缀：ods_（贴源）/ dwd_（明细）/ dws_（汇总）/ ads_（应用）/ dim_（维度）/ fact_（事实）
- 表名：`{层级}_{域}_{主题}_{实体}`，全小写下划线，如 `dwd_population_person`
- 字段：业务语义英文，避免拼音；布尔用 `is_`/`has_` 前缀；时间用 `_time`/`_date` 后缀
- 主体标识约定：自然人 `id_number`、法人 `uscc`（统一社会信用代码）
- 禁止保留字、禁止无意义缩写

### 指标口径管理

- 指标三要素：业务口径（算什么）、计算逻辑（怎么算）、统计维度（按什么切）
- 政务示例：办件量、办结率、好评率、共享调用量、数据鲜活度
- 每个指标唯一口径、唯一 Owner、唯一生效版本，变更走审批

### 业务术语表模板

术语 | 英文 | 定义 | 同义词 | 所属域 | Owner | 关联指标/字段 | 状态

## 元数据与血缘

- 业务元数据：业务术语、指标口径、数据 Owner、共享/开放属性
- 技术元数据：库表结构、字段类型、ETL 任务、分区、存储
- 管理元数据：血缘、质量规则、访问权限、生命周期、密级
- 采集方式：数据库直连（JDBC）、SQL 解析、调度系统日志、共享平台调用日志
- 血缘粒度：表级 → 字段级；典型用途：影响分析、指标异常根因定位、冗余识别
- 数据地图：按部门/主题/基础库组织，每张表必备中文名、业务含义、Owner、更新频率、共享/开放属性

## 基础库与主数据建设

### 识别

政务主数据即基础库核心数据项：自然人、法人、不动产/空间单元、电子证照、信用主体。

### 建设六步

1. 确定权威源与责任部门
2. 制定统一数据元与代码集
3. 多源比对与清洗（人口库与民政、人社、卫健数据比对）
4. 建立唯一标识（自然人：身份证号；法人：统一社会信用代码）
5. 共享分发（接口/批量，明确时效与失败处理）
6. 运维（变更管理、质量监控、争议处理、死亡/注销等状态更新）

### 常见问题

- 权威源不清、多源冲突：先定 System of Record，再定冲突规则
- 只建库不共享：价值在共享，分发链路必须打通
- 数据更新不及时：死亡、注销、迁出等状态变更未同步
- 证照数据未电子化或要素不全
