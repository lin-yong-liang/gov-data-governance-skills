# 数据治理体系设计与成熟度评估（政务/公共数据）

## 适用场景

- 政务数据治理现状评估、DCMM 贯标/评级
- 政务数据治理规划、三年行动方案
- 公共数据开发利用顶层设计
- 跨部门治理组织与制度设计
- 治理成效指标与考核体系设计

## 政务数据治理常见现状问题

- 目录不全、更新滞后，"有数据无目录"
- 一数多源、口径不一，权威源不清
- 部门"不敢共享、不愿共享、不会共享"
- 数据质量责任不清，问题无人整改
- 平台重复建设，数据不汇聚、不回流
- 数据治理与业务脱节，缺考核抓手

## DCMM（GB/T 36073-2018）8 个能力域

| 能力域 | 核心关注 |
|---|---|
| 数据战略 | 战略规划、实施路径、价值评估 |
| 数据治理 | 组织、制度、沟通机制 |
| 数据架构 | 数据模型、分布、集成共享、元数据 |
| 数据应用 | 数据分析、开放共享、数据服务 |
| 数据安全 | 安全策略、安全管理、安全审计 |
| 数据质量 | 质量需求、检查、分析、提升 |
| 数据标准 | 业务术语、参考数据、主数据、数据元、指标 |
| 数据生存周期 | 需求、设计、开发、运维、退役 |

成熟度 5 级：1 初始级 → 2 受管理级 → 3 稳健级 → 4 量化管理级 → 5 优化级。
每能力项按 0–5 打分，证据须落到制度文件、系统功能、目录数据或流程记录。

## 工作流程

1. **摸底**：部门调研、系统与数据资产盘点、目录核查、共享需求收集
2. **评估**：DCMM/自建指标逐项打分，证据留档
3. **差距**：目标 vs 现状，形成问题清单与优先级
4. **蓝图**：组织、制度、目录、标准、平台、安全"六位一体"
5. **路线图**：速赢（0–3 月）→ 建设（3–12 月）→ 深化（12–36 月）
6. **运营**：指标、例会、通报、考核

## 评估方法

- 评分规则：0 = 未开展；1 = 临时性；2 = 有流程未固化；3 = 制度化并主要部门执行；4 = 量化管理；5 = 持续优化
- 政务补充证据：目录编制覆盖率、共享满足率、数据鲜活度、接口调用成功率
- 访谈对象：数据局/大数据中心、业务部门、系统承建单位、使用方代表
- 常见陷阱：只看平台演示不看数据；把"已汇聚"等同于"已治理"；评分无支撑材料

## 组织架构（政务）

- **决策层**：数字政府/数据要素工作领导小组（审定战略、制度、重大事项）
- **管理层**：数据局/大数据中心（统筹目录、共享、质量、安全、考核）
- **执行层**：部门首席数据官（CDO）/数据专员（负责本部门数据目录、质量与共享）
- **支撑层**：专家咨询委员会、平台运营服务商

RACI 示例——政务数据目录发布：部门数据专员 编制(R)、部门 CDO 审核(A)、数据局 审定/发布(R)、技术支撑单位 支撑(C)、使用部门 知会(I)。

## 制度体系四级

1. 总纲：政务数据管理办法
2. 办法：目录管理、共享管理、质量管理、安全管理、开放管理、授权运营管理
3. 细则：考核细则、授权运营实施细则、争议处理细则
4. 规范/模板：目录编制规范、数据元规范、质量检查表、共享协议模板

## 关键机制

- **目录管理**：一数一源、谁提供谁负责、变更即更新
- **共享管理**：共享责任清单 + 需求清单 + 负面清单（附法定依据）
- **质量管理**：提供方负责、使用方反馈、数据局考核
- **安全管理**：分类分级、脱敏、授权运营合规评估
- **争议处理**：权威源争议由数据局裁定

## KPI 示例

- 目录编制覆盖率、目录更新及时率
- 共享责任清单完成率、共享需求满足率
- 数据质量合格率、问题整改闭环率
- 基础库数据鲜活度、接口调用成功率
- 开放数据集数量、开放数据下载/调用量
- 授权运营场景数、合规评估通过率

## 交付物

- 现状评估报告（含证据清单）
- 治理蓝图与实施方案
- 组织架构与制度体系文件
- 政务数据目录与责任清单
- 三年路线图与考核办法

## 注意事项

- 政务治理核心是"责任"不是"技术"，先定权威源和责任部门
- 避免只建平台不建目录、只汇数据不治质量
- 省/市/县多级架构下明确各级职责与数据回流机制
- 指标必须可统计、可通报、能纳入绩效考核
